# 端到端自动驾驶范式笔记

> 依据：`e2e_ad_challenges_frontiers_2306.16927`（270+ 篇综述，OpenDriveLab）+ `e2e_ad_recent_advancements_survey_2307.04370` + UniAD 论文。

## 1. 什么是端到端自动驾驶

**定义**：端到端系统是"完全可微的程序：原始传感器输入 → 规划轨迹/底层控制输出"，感知、预测、规划共享特征、联合优化（综述一 Fig. 1）。

与模块化管线（感知→预测→规划→控制各自独立训练）相比：

| 维度 | 模块化 | 端到端 |
| --- | --- | --- |
| 目标 | 各模块独立优化（检测追 mAP，规划追安全/舒适） | 全系统对齐最终规划目标 |
| 误差 | 逐模块误差累积、信息丢失 | 特征直接传递，减少信息损失 |
| 计算 | 多模型多编码器，冗余计算 | 共享 backbone，更省 |
| 可解释性 | 强（每个模块可查） | 弱（黑盒），但可加中间任务/注意力图缓解 |
| 扩展性 | 数据驱动提升有限 | 数据+算力直接换性能 |

注意：端到端 ≠ 纯黑盒。主流做法保留中间表示/输出（如 BEV、语义分割、占用网格），只是所有模块在一个网络中端到端优化（UniAD 即此路线的代表）。

## 2. 方法分类

### 2.1 模仿学习（IL）

- **行为克隆（BC）**：监督学习，最小化 expert 动作与预测的差距。简单高效，但存在 covariate shift（训练分布与部署分布不一致）和 causal confusion（学到虚假相关性，如刹车与前方车辆无关的线索）。缓解：DAgger（在线聚合数据）、数据聚合、多传感器消歧。
- **逆最优控制（IOC/IRL）**：从 expert 演示学奖励/代价函数，再用轨迹采样器选最小代价轨迹。代表：以 BEV 代价体规划（如 VAD2 一系）、GAIL。可解释性与安全性更强。

### 2.2 强化学习（RL）

- 直接学 Q 值/策略，或 IL 预训练 + RL 微调；通常需要模拟器（CARLA）。
- 现状：尚无纯 RL 达到 IL 的闭环表现（梯度信号不足以训练深层感知网络）；常与特权信息结合用于"生成数据/标签"（Roach、WoR），即**用 RL 特智能体给传感器策略造伪标签**——和用户"伪标签数据上量"的思路有交集。

### 2.3 策略蒸馏（policy distillation）— 与你目标最相关的范式

```
特权智能体（access 真值/强监督）───→ 特征蒸馏 + 输出模仿 ───→ 传感器策略（只用原始输入）
```

代表：Learning by Cheating、Roach、LBC。这也正是"用一个强大教师（如 DINOv3）把特征蒸馏给学生"的自动驾驶版本。

## 3. 表征设计（4.2 视觉抽象）

- 政策学习需要"好"的中间表征：CNN 特征、BEV、语义分割、深度、占用网格（occupancy）、向量化地图等。
- **BEV 已成为主流中间表征**（BEVFormer 一系），把多相机透视特征投影到鸟瞰空间，天然适配规划。
- 关键论断（综述原文）：**"用大规模无标注数据做自监督表征预训练用于策略学习是很有前景的方向"**，代表 PPGeo（自监督几何建模）、ViDAR（点云预测预训练）、ACO（对比学习）。
- 辅助任务（分割/深度/检测）帮助 encoder 提取决策相关信息，但人工定义的伪标签任务可能成为瓶颈——这正是**用 SSL 特征替代这些监督任务**的动机。

## 4. 评测体系

| 类型 | 环境 | 指标 | 说明 |
| --- | --- | --- | --- |
| 闭环（closed-loop） | CARLA、nuPlan、Bench2Drive | 路线完成率（RC）、驾驶分数（DS）、碰撞率、违规数、L2 | 测真实部署分布，推荐但实现复杂 |
| 开环（open-loop） | nuScenes、Argoverse、Waymo | 规划 L2 误差、碰撞率（3s 规划视野）、辅助指标 | 简单可复现，但无法测自恢复能力；多模态轨迹会被惩罚 |
| 真车 | 实车路测 | 安全/舒适指标 | 成本极高 |

结论：学术上用 nuScenes 开环 + CARLA/nuPlan 闭环组合；**用户阶段目标中的 nuScenes 属于开环**，指标即 UniAD 的 avg.L2 与 avg.Col。

## 5. UniAD 案例（Planning-oriented Autonomous Driving, CVPR 2023）

### 架构

一个网络内完成 5 个任务，全部服务规划：

```
多相机 ─→ BEVFormer 编码器 ─→ TrackFormer（跟踪）──┐
                                 MapFormer（建图）──┼→ MotionFormer（运动预测）
                                                       ├→ OccFormer（占用预测）
                                                       └→ Planner（规划，无 HD map）
```

- 所有模块通过统一 query 接口通信（track query / map query / motion query / occupancy）。
- 规划：预测 ego 未来轨迹，再用占用区域做后处理优化（避免碰撞）；无需 HD map。
- 训练：先训感知部分（6 epochs），再全模型端到端 20 epochs（两阶段更稳）。

### nuScenes 上的指标（开环）

| 任务 | 指标 | UniAD 结果 |
| --- | --- | --- |
| 跟踪 | AMOTA / IDS | 0.358 / 641 |
| 建图 | IoU-lane / IoU-road | 0.302 / 0.672 |
| 运动预测 | minADE / minFDE / MR | 0.728 / 1.054 / 0.154 |
| 占用预测 | IoU-near / VPQ-far | 52.8 / 32.3 |
| 规划 | **avg.L2（m）↓ / avg.Col（%）↓** | **1.004 / 0.430** |

消融结论：预测任务显著帮助规划；感知任务（跟踪/建图）显著帮助预测（minADE −9.7%）；全任务联合（Exp.12）比朴素多任务（Exp.0）全面大幅提升（avg.L2 −0.15m、avg.Col −0.51%）。

## 6. 挑战与未来趋势

主要挑战：多模态融合、视觉抽象、世界模型、多任务学习、可解释性、安全保证、因果混淆（causal confusion）、鲁棒性/泛化（sim-to-real、地理/天气/昼夜域偏移）。

未来趋势：

1. **数据引擎（Data Engine）**：自动化标注管线 + 难例挖掘 + 场景生成——即"数据上量"的工程化路径。
2. **基础模型/预训练**：视觉预训练（DINOv3 一类）、大语言模型、世界模型进入驾驶框架。
3. **模块化端到端（modular E2E）**：保留可解释模块边界、但全系统联合优化（UniAD、MP3、ST-P3 路线）。
4. 零样本/少样本泛化。

## 7. 与你总目标直接相关的文献锚点

- 综述一 4.2.1：自监督表征预训练（PPGeo、ViDAR）已证明对策略学习有效。
- 综述一 5.3：数据引擎需要"用大规模感知模型自动打标签"——DINOv3 冻结特征可作为标注质量更高的监督源。
- 综述一 5.4：基础模型适配驾驶的正确姿势是"训练世界模型 + 下游规划"，而非直接 LLM 输出。
- UniAD：展示了"感知任务服务于规划"的耦合方式；替换感知监督信号时应保持这种 query 化的任务间通信。
